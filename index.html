Edge · Cloud · Visual QA

Why task-aware routing?

Sending every image to a cloud model can add network payload and latency, even when a lightweight local model can answer the question.

01

Understand the request

Qwen classifies the question by intent: count, list, attribute, OCR, or complex reasoning.

02

Choose a route

The router selects object detections, local visual understanding, or cloud inference as appropriate.

03

Measure the trade-offs

We track answer quality, transferred payload, and end-to-end latency for edge-oriented use.

Approach

Recorded input images and a user question enter the same pipeline; only the selected route processes or transmits visual data.

Built, tested, and next

Current evaluation uses recorded images—not live camera input or a simulated sensor.

Implemented What we built

  • Question classification and task-aware routing
  • YOLO detection, object crops, and route fallbacks
  • Local SmolVLM and DeepSeek cloud integration
  • Payload, latency, and per-image result reports

Tested Current evidence

  • Recorded-image replay on Raspberry Pi and Windows PC
  • Small task-specific image sets; sample counts vary
  • Accuracy still needs a labeled, controlled comparison
  • Qwen routing errors and cloud-service failures remain risks

Design goal

Reduce communication and response costs while preserving useful visual answers.
